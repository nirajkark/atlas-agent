01

Where the two services sit

Run Control decides what state things should be in. Process Management decides whether the binaries are alive. Everything they observe lands in the Information Service, which is where an agent should read from.

02

The control tree, and why a parent's state is a summary

Commands travel down. States travel back up and get aggregated — which means a controller's reported state is a conclusion drawn from its children, not something it observed directly.

The root is not like the others

The FSM is a template parameterised on its initial state, and the transition table is chosen at compile time. A child controller's table does not merely guard the root-only transitions — it does not contain them. So SHUTDOWN, INITIALIZE and RELOAD_DB are legal at the root and non-existent everywhere else, and "which transitions are legal here?" has two different answers for two nodes in the same state.

09

Three vocabularies, six collisions

The two services carry three different notions of "what this component is doing" — and the names overlap while the meanings do not. This is the central safety problem for any agent built on top.

Why a system prompt cannot fix this

By the time text reaches the model, a tool has already returned state: "RUNNING". The ambiguity is in the data, not the wording — no prompt recovers a distinction the payload never carried. The fix has to be structural: values get typed by vocabulary before they reach the model, so rc.fsm:RUNNING and pmg.process:RUNNING cannot compare equal.

10

How stale is the answer?

The two services publish on completely different schedules, so "as of when?" has a different answer depending on which one you asked.

And a second, sharper trap

Every status record carries two timestamps in nanoseconds. One is wall-clock time. The other is a monotonic ordering token that the source explicitly says "may have no relationship at all with the clock time" — it exists so the publisher can discard out-of-order updates. Render that one as a date and the agent produces precise, confident, entirely fictitious answers to "when did this happen".
